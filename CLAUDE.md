# Portfolio AS-WebDev

## Projet

Ce projet est le portfolio et le site vitrine de ma micro-entreprise AS-WebDev.

Objectifs :

- Présenter mes services de développement web.
- Inspirer confiance dès les premières secondes.
- Générer des prises de contact qualifiées.
- Mettre en avant mon expertise et mon professionnalisme.
- Offrir une expérience moderne, fluide et premium.

---

## Stack

- Next.js (App Router)
- React
- TypeScript
- Tailwind CSS

Toujours privilégier les fonctionnalités natives de Next.js et React avant d'ajouter une dépendance externe.

---

## Design

Le design doit être :

- moderne
- premium
- minimaliste
- élégant
- responsive
- mobile-first
- rapide
- accessible

Palette principale :

- Noir
- Vert émeraude

Éviter :

- les interfaces surchargées
- les animations excessives
- les effets "gadget"

Les animations doivent rester discrètes et améliorer l'expérience utilisateur.

---

## Philosophie de développement

Je privilégie :

- la simplicité
- les bonnes pratiques
- la maintenabilité
- la lisibilité
- les performances
- l'accessibilité
- le SEO

Avant d'ajouter une nouvelle dépendance, vérifier qu'une solution native n'existe pas déjà.

---

## Qualité du code

Toujours :

- utiliser TypeScript strictement
- éviter les `any`
- créer des composants petits et réutilisables
- utiliser des noms explicites
- éviter la duplication de code (DRY)
- factoriser uniquement lorsque cela améliore réellement la lisibilité
- respecter l'architecture existante

Les commentaires doivent uniquement expliquer une intention ou un choix technique, jamais décrire un code évident.

---

## Avant chaque modification

Avant d'écrire du code :

- analyser l'existant
- expliquer brièvement ce qui va être réalisé
- vérifier que la solution reste cohérente avec l'architecture actuelle

Ne jamais réécrire un fichier entier si quelques modifications ciblées suffisent.

---

## Si une meilleure solution existe

Ne pas modifier directement.

Expliquer :

- pourquoi la solution actuelle peut être améliorée
- les avantages
- les inconvénients
- proposer une alternative

Je préfère être challengé plutôt que simplement approuvé.

---

## UX

Toujours privilégier :

- une navigation intuitive
- une excellente lisibilité
- des interfaces claires
- un responsive irréprochable
- un temps de chargement minimal
- une expérience utilisateur premium

Chaque élément affiché doit avoir une réelle utilité.

---

## SEO

Lorsque c'est pertinent :

- utiliser les Metadata API de Next.js
- respecter la hiérarchie des titres
- utiliser les balises HTML sémantiques
- optimiser les performances Lighthouse
- favoriser un bon référencement naturel

---

## Communication

Toujours répondre en français.

Lorsque plusieurs solutions existent :

- expliquer brièvement leurs avantages et inconvénients
- recommander celle qui semble la plus adaptée

Ne cherche pas à valider mes idées automatiquement.

Si tu penses qu'une décision est mauvaise, explique pourquoi et propose une meilleure approche.

---

## Vision produit

Ce site n'est pas seulement un portfolio, c'est un véritable outil commercial.

Chaque section doit contribuer à transformer un visiteur en prospect.

Lorsqu'une amélioration est proposée, réfléchir aussi à son impact sur :

- la crédibilité
- la confiance
- la compréhension des offres
- la prise de contact
- le taux de conversion

Si une amélioration peut augmenter la conversion sans complexifier inutilement l'interface, propose-la systématiquement.

Réfléchis comme un développeur senior, mais aussi comme un UX Designer et un spécialiste de la conversion (CRO).

---

## Apprentissage

Lorsque tu proposes une modification importante ou une nouvelle architecture, explique brièvement le raisonnement qui t'a conduit à cette solution.

L'objectif est que je comprenne les choix techniques afin de progresser, pas seulement d'obtenir un résultat fonctionnel.
